# Перенос на Тильду

Сайт свёрстан в коде, потому что дизайн «тёмная сцена, один символ, один свет»
в конструкторе не собирается штатными блоками. Этот файл — план переноса, если
решение всё-таки менять на Тильду.

Честно: **полного 1:1 переноса не будет**. Ниже что переносится, что собирается
костылем и что теряется.

## Что теряется при переносе

| Приём в коде | В Тильде |
|---|---|
| Нить — SVG-кривая, прочерчивается при появлении секции (`main.js`, `.thread`) | Только Zero Block + свой JS в `T123`. Работает, но править кривую придётся мышкой в ноунейм-блоке |
| Зерно поверх страницы (`body::after`, SVG-фильтр) | Кастомный CSS в настройках сайта — ок |
| `prefers-reduced-motion`, `prefers-reduced-data` | Ок, тем же CSS |
| Чистые URL `/for-local` | Тильда даёт `/l/1234567` или ручную настройку адреса страницы. Чистый URL на подпапку вида `/subscribe/start` — **недоступен**, будет `/subscribe-start` |
| Квиз с подсчётом баллов и редиректом на страницу ЦА | Нативный квиз Тильды (T551/T552) умеет шаги и «показать блок», но **не умеет** редирект на другую страницу по сумме баллов. Либо `T123` со своим JS, либо редирект через скрытое поле + настройку формы |
| Формы с UTM в скрытых полях | Родная механика Тильды: `input type=hidden` в поле «Другое» + автоподстановка UTM. Работает из коробки |
| `mix-blend-mode: screen` на символах | Работает, если картинка лежит на тёмном фоне без белой подложки блока |
| Скорость: 20 КБ постер, нет jQuery | Тильда тянет ~400–600 КБ своих скриптов и шрифтов. LCP ≤2,5 с на мобильном удержать можно, но с запасом не получится |

## Подготовка проекта

1. **Настройки сайта → Основной** — домен `direct-ad.ru`, без `www`.
2. **Настройки сайта → Шрифты** — добавить вручную, родного списка на три шрифта не хватит:
   - `Cormorant Garamond` 400/500/600 — заголовки
   - `Oswald` 400/500/600 — метки и цифры
   - `Manrope` 400/500/700 — текст
   Все три есть в Google Fonts с кириллицей. В Тильде: «Добавить шрифт» → указать имя и веса.
3. **Настройки сайта → HTML-код → Шаблон → `<head>`** — вставить `<link>` на `main.css`,
   если будешь держать файл на хостинге, либо перенести содержимое `main.css` целиком в
   «CSS-код» (см. ниже, что выкинуть).
4. **Фавикон** — `assets/img/favicon.svg`, 64×64.

## Куда что класть

### Общий CSS

Из `main.css` в поле «CSS-код» Настроек сайта переносить **не всё**.

Переносить: секции 1 (токены), 4 (типографика), 8 (нить), 23 (появление), 24 (печать),
правила `.who__*`, `.includes*`, `.leak*`, `.expert*`, `.tier*`, `.compare*`, `.faq*`,
`.form*`, `.field*`, `.choice*`, `.consent*`, `.after*`, `.progress*`, `.quiz*`,
`.sticky-cta`, `.cookie`, `.ph`, `.empty-state`, `.other-plans`, `.channels`.

**Не переносить** (Тильда сломает или это конфликтует с её стилями):
сброс `*`, `html`, `body` (у Тильды свои), `.site-header`, `.mobile-nav`, `.site-footer`,
`.shell`, `.section`, `.hero*`, `.brand`, `.nav*`, `.menu-toggle`, `.skip-link`.
Оболочку, шапку и подвал делает Тильда — свои блоки.

Все селекторы в переносимом CSS лучше обернуть в область, чтобы не задеть стили Тильды:
добавь каждой секции класса префикс-контейнер, например `.da-wrap .who__row { ... }`.
В Zero Block это делается через поле «CSS-класс» у группы.

### Формы

Родная форма Тильды (`BF702`) вместо HTML-форм из кода. Настроить так:

1. Поля: `Имя` (name), `Телефон или Telegram` (phone), скрытые — `tariff`, `audience`,
   `source`, `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`,
   `yclid`, `page`.
   Скрытые поля: «Другое» → тип `hidden`, значение подставляется автоматически
   (`{utm_source}` и т.д. из автополей Тильды).
2. **Согласие**: включить в настройках формы «Чекбокс согласия» и вписать текст со ссылкой
   на `/privacy`. Предустановленная галочка запрещена 152-ФЗ — Тильда по умолчанию её не ставит,
   не включай.
3. **Отправка**: Настройки формы → «Отправка на e-mail» (hello@direct-ad.ru) + «Telegram-бот»
   (нужен токен — **не храни его в коде**, только в поле интеграции).
4. После отправки: «Страница благодарности» → `/thanks`.

### Аналитика

Счётчик Метрики ставится один раз: Настройки сайта → «Аналитика» → номер счётчика.
**Не дублировать** кодом в `<head>`, иначе двойные хиты.

Вебвизор, карту скролла и отчёт по формам включить в самом кабинете Метрики.
Цели из `data-goal` пересоздать в кабинете вручную по именам из ТЗ
(`view_for_local`, `click_subscribe_start`, `lead_subscribe_start`, `quiz_start`,
`quiz_step_1…6`, `quiz_complete`, `lead_checklist`, `lead_audit`, `scroll_75`,
`click_telegram`, `click_phone`) — на формах Тильды цели на отправку ставятся
в настройках формы, на клики — через «Отслеживание событий» с CSS-классом кнопки.

## Порядок переноса

1. Создать проект, подключить домен, шрифты, favicon.
2. Перенести CSS (обёрнутый в `.da-wrap`) и проверить, что не поехало.
3. Собрать **одну** страницу `/for-local` целиком — это самая плотная по дизайну.
   Если она выглядит как в коде, остальное пойдёт по шаблонам.
4. Раздать якоря и ссылки между страницами (помни: `/subscribe/start` станет `/subscribe-start`).
5. Настроить формы и цели.
6. Только потом переносить `/`, `/pricing`, `/quiz`.
7. `go.direct-ad.ru` — отдельный проект, `noindex`, лёгкие ленды.

## Проверка после переноса

- [ ] Нет горизонтального скролла на 320px (в Тильде проверять в предпросмотре мобильной версии)
- [ ] Все формы доходят на почту и в Telegram, в заявке есть UTM и `tariff`
- [ ] Цели Метрики горят «тест целей» → «достигнута»
- [ ] `noindex` на `/thanks`, `/checklist/thanks`, `/lp/*`, незаполненных `/cases/*`
- [ ] Рекламный бюджет явно указан как «не входит» на `/pricing` и всех `/subscribe-*`
- [ ] ERID и данные рекламодателя в подвале (требования маркировки)
- [ ] Юрист посмотрел `/privacy` и `/oferta`

## Рекомендация

Если Тильда нужна **только** как хостинг — дешевле и быстрее положить эту статику
на обычный хостинг или в Cloudflare Pages, а Тильду не трогать.
Если Тильда нужна, чтобы **самому править тексты без разработчика** — переноси
страницы ЦА и подписки (их правят чаще всего), а `/` оставь в коде как
отдельный проект: на неё водится трафик из Директа, и там дизайн важнее всего.
